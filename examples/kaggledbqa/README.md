# Watching context work: two real Kaggle databases

The teaching example for the context question itself. [KaggleDBQA](https://github.com/Chia-Hsuan-Lee/KaggleDBQA)
is built from real Kaggle datasets with their original messy formatting, and
it ships something rare: human-written column documentation. That
documentation is the context under test - not invented for this example,
used verbatim.

```bash
make example-kaggledbqa    # offline, no key, seconds
```

The predictions are committed (gemini-2.5-flash, temperature 0, three
repetitions per arm, generated by `contextlift generate`), so the command
replays the scoring and the paired comparison deterministically. What it
prints:

```
=== StudentMathScore: baseline vs the dataset's own docs (3 reps pooled) ===
paired ablation on 84 observations (28 questions x 3 reps, execution accuracy)
  without context :  38.1%  [28.4%, 48.8%]
  with context    :  47.6%  [37.3%, 58.2%]
  lift            :  +9.5%  [-6.6%, +20.9%]   (the two rates subtracted; 95% interval on the paired difference, per question)

  each question counted once - the number to defend
    fixed 3 / broke 1 of 28 questions
    p = 0.6250   not significant at 0.05

  each answer counted separately - optimistic, because repeated
  answers to one question are not independent
    fixed 10 / broke 2 of 84 observations
    p = 0.0386   significant at 0.05
  at 28 questions this set can only prove a lift above about 19 points (1/sqrt(28)); to prove the +9.5% seen here you would need about 117 questions

=== GeoNuclearData: baseline vs the dataset's own docs (3 reps pooled) ===
paired ablation on 96 observations (32 questions x 3 reps, execution accuracy)
  without context :  62.5%  [52.5%, 71.5%]
  with context    :  67.7%  [57.8%, 76.2%]
  lift            :  +5.2%  [-2.1%, +14.6%]   (the two rates subtracted; 95% interval on the paired difference, per question)

  each question counted once - the number to defend
    fixed 2 / broke 0 of 32 questions
    p = 0.5000   not significant at 0.05

  each answer counted separately - optimistic, because repeated
  answers to one question are not independent
    fixed 6 / broke 1 of 96 observations
    p = 0.1250   not significant at 0.05
  at 32 questions this set can only prove a lift above about 18 points (1/sqrt(32)); to prove the +5.2% seen here you would need about 88 questions
```

Both databases, same reading lesson, and it is not the one an earlier version
of this page taught:

1. **The per-answer line looks like a win and is not one.** StudentMathScore
   reads `fixed 10 / broke 2, p = 0.0386, significant` if you count every
   repetition as its own observation. Counted per question it is
   `fixed 3 / broke 1 of 28, p = 0.625` - three questions moved, and that is
   not distinguishable from luck. Answering a question three times gives
   three answers, not three independent facts. The tool prints the
   per-question line first for exactly this reason. An earlier version of this
   README quoted only the per-answer number and called this database "the
   clean win"; that was the mistake the tool now refuses to print first.
2. **GeoNuclearData is the same shape, smaller**: 2 fixed, 0 broke, of 32.
   Same direction, and at this size not yet a result. More questions decide
   it, not enthusiasm; the line after the ruling says how many, at these
   rates: about 88 for GeoNuclearData, about 117 for StudentMathScore.
3. `--show` marks questions that flipped between repetitions as unstable -
   `q015` here was fixed in some repetitions and broken in others. That churn
   is invisible in any single run, which is why arms are generated with
   `--reps 3` and pooled: pooling buys a stable estimate of the rate, not
   evidence that more questions would have bought.

## Rebuild it from scratch (paid, ~$0.05)

```bash
python3 prepare.py             # CSVs, schema, docs from the committed files
contextlift gate --timeout 60 --db StudentMathScore.sqlite \
  --golds scratch/StudentMathScore/golds.csv --clean-out scratch/StudentMathScore/golds_clean.csv
contextlift leak --context scratch/StudentMathScore/docs.txt \
  --predictions scratch/StudentMathScore/questions.csv
contextlift generate --questions scratch/StudentMathScore/questions.csv \
  --schema scratch/StudentMathScore/schema.txt --out scratch/StudentMathScore/pred_base.csv \
  --backend gemini --project YOUR_PROJECT --reps 3
# ... same with --context scratch/StudentMathScore/docs.txt, then score + ablate
```

The docs are question-independent, so no curate/holdout split is needed for
this comparison - `leak` proves the context contains no answers.
